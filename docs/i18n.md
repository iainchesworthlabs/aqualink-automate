# Web UI internationalization (i18n)

*How the web UI's translation layer works and how to add a language. The
roadmap and surface analysis live in [docs/i18n-scoping.md](i18n-scoping.md);
this doc describes what is implemented (Phase 0: catalog infrastructure and
full English string extraction).*

## Architecture

- **Catalogs** are plain JS registration files under `assets/web/i18n/`, one
  per locale, each assigning a flat `"namespace.key" → string` map into
  `window.AquaI18n.catalogs.<locale>`. English (`i18n/en.js`) is included
  statically in `index.html` before every other app script, so the default and
  fallback catalog is always available synchronously — no fetch race, no flash
  of raw keys, works offline. Non-English catalogs load on demand via
  `<script>` injection and swap in reactively.
- **Runtime** is `assets/web/scripts/i18n.js`: the locale registry
  (`SUPPORTED_LOCALES`), an Alpine store (`$store.i18n`), the `$t('key',
  {params})` / `$tn('key', count)` template magics, and `window.AquaI18n.t()`
  for plain-function call sites (stores, views, components). Lookup order:
  active locale → English → the key itself (with a one-time console warning,
  so a missed extraction is visible in dev tools).
- **Locale resolution**: explicit user choice (Settings → Appearance →
  Language) is stored in `localStorage` (instant boot) and mirrored to the
  server under `preferences.ui.locale` (cross-device; the server value wins on
  conflict). A user who never chose follows `navigator.language`. `<html
  lang>` and `<html dir>` track the active locale; locales registered with
  `dir: 'rtl'` flip the document direction (no RTL locale ships yet — the CSS
  logical-properties pass is a later phase, see the scoping doc).
- **`/api/preferences` `ui` merge**: the opaque `ui` object merges shallowly
  at its top level on PUT, so `ui.locale` and `ui.chemistryBands` (written by
  independent frontend features) never clobber each other; a top-level null
  deletes the key. See `assets/web/api/swagger.yaml` and
  `TestSuite_PreferencesService/ApplyJson_UiMergesTopLevelKeys`.

## Key conventions

- Flat dot keys, namespaced by surface: `nav.*`, `login.*`, `dash.*`,
  `detail.*`, `diag.*`, `devcard.*`, `trends.*`, `sched.*`, `settings.*`,
  `about.*`, plus shared `common.*`, `status.*`, `cmd.*`, `alert.*`,
  `toast.*`, `time.*`, `tier.*`, `chem.*`, `swg_health.*`, `day.*`.
- Placeholders are `{name}` and are substituted by `t()`; never rebuild
  sentences by string concatenation — word order differs across languages.
- Keys ending in **`_html`** may contain markup (bound with `x-html`; the
  content is static catalog text, never server data). Translations must
  preserve the tags.
- **Plural keys** carry a CLDR category suffix (`.one`, `.other`, …) and are
  looked up via `tn(key, count)` / `$tn` using `Intl.PluralRules` (e.g.
  `sched.conflicts.one` / `sched.conflicts.other`).

## What is deliberately NOT translated

- **Device-originated text**: aux/device labels, pool names, panel screen
  lines, controller program names — these arrive over RS-485 (or are
  user-configured) and pass through verbatim.
- **Technical tokens**: backend enum values used as wire/comparison values
  (the display layer maps the known ones via `status.*` / `swg_health.*`
  catalog keys and falls back to the raw name for unknown values), log
  severity levels and channel names, JSON field names, MQTT payloads, units
  attached to raw diagnostics, endpoint paths, the brand name.
- **Backend prose** (HTTP error bodies, alert `detail` text) still arrives in
  English — converting those to symbolic codes + params is Phase 2 of the
  scoping doc.

## Adding a language

1. Copy `assets/web/i18n/en.js` to `assets/web/i18n/<code>.js`, change the
   registration line's locale code, and translate the **values** (never the
   keys).
2. Register the locale in `SUPPORTED_LOCALES` in `assets/web/scripts/i18n.js`
   with its own-language name (endonym) and text direction.
3. Run the completeness checker against your tree:
   `pwsh scripts/check-i18n-keys.ps1 -Root <repo-root>` — it fails on any key
   referenced in code but missing from the English catalog and lists
   unreferenced catalog keys.
4. The new catalog ships automatically: the build copies and packages
   `assets/web` recursively, and the service worker precaches `i18n/en.js`
   (other locales are cached on first use by the runtime caching layer).
